# MEDICAL RP

Самостоятельная игровая платформа о работе виртуальной больницы: восемь специальностей, локальный профиль, две миссии в сутки, MED COINS и косметический магазин. Все медицинские ситуации условные; проект предназначен для развлечения. Связей и интеграций с BLACK RUSSIA нет.

Сайт работает в браузере без регистрации, серверного приложения и внешней базы данных. Для игры достаточно статического хостинга. Three.js, шрифты и остальные ресурсы находятся в репозитории; CDN для запуска не требуется.

## Запуск

Нужен любой HTTP-сервер статических файлов. Например, из корня репозитория:

```sh
python3 -m http.server 8080 --bind 0.0.0.0
```

Откройте `http://localhost:8080`. На телефоне в той же сети используйте IP компьютера и порт 8080. Открытие `index.html` через `file://` не поддерживается: браузер ограничивает загрузку ES-модулей. Node.js нужен только для автоматических проверок исходников; сервер Node.js для сайта не используется.

## GitHub Pages

Workflow [pages.yml](.github/workflows/pages.yml) при каждом push в `main` проверяет исходники и правила игры, затем публикует статический артефакт официальными GitHub Actions. Сборки приложения и установки npm-зависимостей нет. Путь проекта поддерживается относительными ссылками.

Перед первой публикацией в репозитории откройте **Settings → Pages → Build and deployment → Source: GitHub Actions**. Затем запустите **Actions → Deploy MEDICAL RP to GitHub Pages → Run workflow** или отправьте изменения в `main`. Обычный `GITHUB_TOKEN` workflow не может впервые включить Pages; для этого нужны права на настройки репозитория. Для последующих публикаций используются разрешения `pages: write` и `id-token: write`, указанные в workflow. Дополнительные токены и секреты в workflow не требуются.

Ожидаемый адрес: <https://electrostatic14.github.io/medicalrp/>. Фактический адрес опубликован в успешном запуске задания `deploy` и в разделе **Environments → github-pages**. Push сам по себе не подтверждает успешную публикацию: проверяйте статус Actions.

## Специальности и управление

Перед каждой миссией доступны обучение и три уровня сложности. Прикосновение на телефоне соответствует клику мышью на компьютере. Инструменты выбираются крупными кнопками; для перетаскивания удерживайте объект и перемещайте палец или мышь. Игровая область блокирует случайную прокрутку во время точных действий.

| Специальность                         | Игровая задача                              | Основные действия                                                     | Рекомендуемая ориентация |
| ------------------------------------- | ------------------------------------------- | --------------------------------------------------------------------- | ------------------------ |
| Интерн — «Первое дежурство»           | Очередь пациентов и заполнение карт         | Выбор пациента, приборы, интерактивные измерения, приоритет обращения | Вертикальная             |
| Парамедик — «Экстренный вызов»        | Комплектация и работа на месте происшествия | Выбор снаряжения, последовательность помощи, реакция и ритм           | Горизонтальная           |
| Фельдшер — «Стабилизация»             | Пациент и оборудование в 3D-палате          | Выбор инструмента, касание объекта сцены, ритм и удержание            | Горизонтальная           |
| Нарколог — «Токсикологический анализ» | Лабораторное расследование                  | Анализатор, работа с образцами, сопоставление результатов             | Вертикальная             |
| Педиатр — «Маленькие пациенты»        | Доверие и осмотр ребёнка                    | Диалог, игрушки, интерактивные исследования                           | Вертикальная             |
| Терапевт — «Клинический детектив»     | Построение диагноза по доказательствам      | Диалог, бюджет исследований, улики и гипотезы                         | Вертикальная             |
| Травматолог — «Реконструкция»         | Поиск повреждений и сборка фрагментов       | Масштабирование, перетаскивание и вращение фрагментов                 | Горизонтальная           |
| Хирург — «Операционная»               | Пять типов многоэтапных операций в 3D       | Инструменты, траектории, удержание и совмещение                       | Горизонтальная           |

В 3D вращайте камеру одним пальцем или мышью, масштабируйте двумя пальцами или колёсиком. Для процедуры используйте режим точности и доступные ракурсы: во время манипуляции камера фиксируется. Следуйте текущей цели над сценой. Подробное обучение каждой специальности доступно перед запуском. Поворот устройства рекомендован, но не блокирует игру.

В настройках доступны качество графики, музыка, громкость эффектов и полноэкранный режим, если браузер его поддерживает. Браузеры разрешают звук после первого действия пользователя. На слабом устройстве выберите низкое качество; 3D загружается при открытии соответствующей игры и освобождает ресурсы при выходе. Цели производительности — 30 FPS на среднем и 60 FPS на мощном устройстве; фактическая частота зависит от устройства и браузера.

## Попытки, награды и сохранения

**Две попытки в сутки суммарно на все восемь игр.** Попытка расходуется при запуске миссии, включая повторный запуск той же специальности. Выход, поражение и обновление страницы её не возвращают. Продолжение сохранённой миссии повторно попытку не списывает. На экране отображаются остаток и обратный отсчёт до полуночи в **Asia/Almaty**. Для определения суток используется часовой пояс Алматы, а не часовой пояс устройства.

За миссию начисляются XP и MC в зависимости от результата. Максимальная награда: Интерн 100, Парамедик 130, Фельдшер 170, Нарколог 180, Педиатр 150, Терапевт 190, Травматолог 220, Хирург 300 MC. Множители оценки: S — 100%, A — 85%, B — 65%, C — 40%, D — 20%. MC оплачивают только применяемую косметику: рамки, темы, титулы, оформление инструментов, фон и эффект победы. Дополнительные попытки не продаются.

Баланс, опыт, достижения, инвентарь, настройки, рекорды, история и активная миссия сохраняются в `localStorage` с ключом `medical-rp:profile:v1`. При случайном закрытии вкладки вернитесь и продолжите миссию с последнего сохранения. Очистка данных браузера удаляет прогресс; переноса между устройствами и облачной синхронизации нет. В приватном режиме или при переполненном хранилище постоянное сохранение может быть недоступно.

Это статическая игра: пользователь контролирует свои локальные данные и часы устройства. Намеренное удаление/изменение хранилища может обойти лимит; серверной защиты или античита здесь нет. Для полного удаления прогресса предусмотрена настройка с дополнительным подтверждением.

## Структура

```text
index.html                  оболочка приложения
css/                        интерфейс, адаптация и стили игр
js/app.js                   навигация, профиль, результаты и магазин
js/catalog.js               специальности, предметы и достижения
js/storage.js               нормализация и локальное сохранение
js/progress.js              сутки Алматы, попытки, XP, награды и покупки
js/audio.js                 синтез звука через Web Audio API
js/game-kit.js              таймер, HUD и общий жизненный цикл
games/                      восемь отдельных игровых ES-модулей
assets/vendor/              локальная Three.js и OrbitControls
assets/fonts/               локальный Manrope
tests/                      проверки правил, ресурсов и браузерный smoke-тест
.github/workflows/pages.yml публикация GitHub Pages
```

Игровой модуль экспортирует `mount(ctx)` и возвращает объект с `destroy()`. Оболочка передаёт ему сложность, сохранённое состояние, настройки, аудио и функции сохранения/завершения. Награды выдаёт общий модуль прогресса, поэтому игровые модули не изменяют баланс напрямую. 3D-сцены загружаются лениво. При выходе модуль обязан убрать обработчики, таймеры и ресурсы WebGL.

## Проверки

Для проверки синтаксиса, локальных импортов и ресурсов, полноты каталога и правил прогресса нужен Node.js 22 или новее:

```sh
npm run check
npm test
```

Браузерный smoke-тест требует Python 3, Playwright и Chromium. Это инструменты разработки, они не входят в игровой сайт:

```sh
python3 -m pip install playwright pillow
python3 -m playwright install chromium
python3 tests/browser_smoke.py
```

Тест сам запускает временный статический HTTP-сервер. Для уже работающего сайта:

```sh
python3 tests/browser_smoke.py --base-url http://localhost:8080 --chromium /usr/bin/chromium
```

Проверяются загрузка на мобильном и настольном экране, основные разделы, восемь запускаемых миссий, сохранение/продолжение, лимит попыток, ошибки браузера и отображение WebGL-сцен. Отдельные сценарии проходят всех шестерых пациентов Интерна с перетаскиванием и процедурами, проверяют награды, покупают и применяют все шесть видов косметики, проверяют поражение по таймеру и блокировку третьей попытки. Тест использует отдельные временные браузерные профили и может менять только их локальные данные для сценариев проверки; в игре нет тестового интерфейса или обхода лимита. Скриншоты и отчёт сохраняются в игнорируемый каталог `test-results/`. Smoke-тест не заменяет ручное прохождение всех сценариев на реальных Android/iOS и проверку производительности на устройствах.

При подготовке проекта прошли 20 модульных тестов и проверка синтаксиса, связности ES-модулей и локальных ресурсов. В Chromium проверены настольный экран 1440 px, мобильный 390 px и горизонтальный 844 × 390 px: навигация, старт и продолжение всех восьми игр, настоящий WebGL-контекст и непустое изображение обеих 3D-сцен. Проверены шесть покупок с точным списанием MC, сохранение оформления, золотые инструменты и эффект победы. Полная миссия Интерна завершена на 100 баллов: 42 верных действия, 0 ошибок; дополнительно проверены продолжение после обновления, награды, поражение по таймеру и блокировка третьей попытки. Отдельная проверка удержания указателя подтверждает, что игровая мишень не смещается между нажатием и отпусканием. Измерений FPS на реальных смартфонах и проверки Safari на iOS пока не проводилось.

## Зависимости и лицензии

- Three.js **0.170.0**, включая OrbitControls, поставляется локально. Лицензия MIT: [THREE-LICENSE.txt](assets/vendor/THREE-LICENSE.txt).
- Шрифт Manrope поставляется локально. Лицензия OFL: [LICENSE.txt](assets/fonts/LICENSE.txt).
- Изображения и сцены игрового окружения строятся клиентским кодом, звуки синтезируются через Web Audio API. Для игрового процесса не нужны внешние API, учётные записи или ключи доступа.
